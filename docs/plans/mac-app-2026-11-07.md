# Folio for Mac Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A real `Folio.app` for Apple Silicon Macs: its own window and Dock icon, Folio's server running inside it, and updates that install themselves from GitHub Releases.

**Architecture:** A Tauri 2 shell (Rust, using the Mac's built-in WebKit) starts Folio's existing Hono server as a sidecar with a bundled Node 24, waits for `/api/health`, then points its window at `http://localhost:5174`. The web app and the data folder (`~/ResearchPlatform`) don't change. The page gets no Tauri IPC: links, downloads, window behavior and updates are all handled in Rust.

**Tech Stack:** Tauri 2.9 (`tauri`, `tauri-plugin-shell`, `-updater`, `-dialog`, `-opener`, `-process`, `-single-instance`, `-window-state`), Node 24.22.2 (runs `server/*.ts` directly, no tsx), GitHub Actions `tauri-apps/tauri-action@v0`.

**Spec:** The Lattice comparison in this session plus the decisions below (no separate spec file). Lattice (`/Applications/Lattice.app`) shows the target shape: a Tauri shell, bundled Node, Developer ID signed and notarized, and a `latest.json` updater on GitHub Releases.

## Decisions already made

- **Node runs the server's TypeScript as is.** Checked on 2026-11-07: `node server/index.ts` on Node 24 serves `/api/health`, `/` and `/api/projects` (tsconfig has `erasableSyntaxOnly` and `verbatimModuleSyntax`).
- **The bundle carries only the server's packages.** A full production install is 599 MB. Only the 17 packages the server imports are needed: 102 MB, checked running. The UI is already compiled into `dist/` (9 MB).
- **Same data folder, same port.** Use `~/ResearchPlatform` (no migration) and port 5174. localStorage (music, pomodoro, folded sidebar) is keyed by origin, so the port must stay stable between launches.
- **Releases go in the public repo `akamoe/research-platform`.** `folio-online` is private, so the updater couldn't download `latest.json` from it without a login.
- **arm64 only for now.** `@firecrawl/pdf-inspector` has no Intel build. Windows and Linux reuse this shell later and are out of scope here.

## Decisions for Moe (before or during the work)

1. **Which repo gets the code.** Recommended: `research-platform` on a new branch, since installers and updates already point there. This plan only touches files both repos share (`server/index.ts`, `server/update.ts`, `src/components/updates.tsx`) plus new files.
2. **Apple Developer Program ($99/year).** Tasks 1–6 work without it: builds are ad-hoc signed, and each person clicks *Open Anyway* in System Settings → Privacy & Security once. Task 7 turns on Developer ID signing and notarization when the account exists.
3. **Publishing.** CI only creates **draft** releases. A draft becomes an update for everyone only when Moe presses Publish on GitHub.

## Global Constraints

- Bundle id `app.folio.desktop`, product name `Folio`, first version `0.1.0`, macOS minimum `14.0`, target `aarch64-apple-darwin`.
- Node pin: `node-v24.22.2-darwin-arm64.tar.gz`, sha256 `aa9549349e47dffaa42dcf95d6e06ade8c4bdafc980979883b88767670df385a`. Refuse to bundle on a mismatch.
- The server runs with `RP_PORT`, `RP_DESKTOP=1`, `RP_DESKTOP_VERSION=<app version>` and `RP_PARENT_PID=<app pid>`. `RP_DATA_DIR` stays unset, so the default is used.
- Ports tried: 5174–5178, in order.
- The updater endpoint is exactly `https://github.com/akamoe/research-platform/releases/latest/download/latest.json`.
- The updater's private key is never committed. It goes in the GitHub secrets `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`.
- Don't use Trellis (non-commercial license) or tldraw (paid key). UI copy is English. The guide gets a section in both `docs/GUIDE.md` and `docs/GUIDE.ar.md`. The README only gets a download link.
- Checks: `npm run typecheck`, `npx vite build`, `npm run test:desktop`, `cargo test --manifest-path src-tauri/Cargo.toml`.

## Review Focus

1. **A Folio is already running on 5174** (the browser launcher). The app reuses it, doesn't start a second server, and leaves it running on ⌘Q. Owned by Task 4 (`choose_port` reuse test plus a manual step).
2. **The app is force-quit or crashes.** The orphaned Node server exits within about 2 s, so the next launch starts clean. Owned by Task 2 (`watchParent` test).
3. **The server stops while the window is open.** The window shows "Folio stopped" with a Restart button and the log path, never a blank page. Owned by Task 4 (manual kill step).
4. **The server gains a new package later.** The bundle picks it up automatically, and a missing one fails the build instead of the app. Owned by Task 3 (`serverDeps` test on the real `server/`).
5. **Downloading the same file twice.** The second copy is `name (1).ext` and never overwrites a file in Downloads. Owned by Task 5 (`unique_path` tests).

  - `[Folio] → Some((5174,true))`

- [ ] **Step 3: Implement `port.rs`.**
  - `probe` does a `TcpStream::connect_timeout` to 127.0.0.1 with a 300 ms timeout. If that fails, the port is Free. Otherwise it sends a raw `GET /api/health HTTP/1.0` and returns Folio or Other.
- [ ] **Step 4: Implement `server.rs`.**
  - Sidecar `node` with the arg `<resource_dir>/app/server/index.ts` and current dir `<resource_dir>/app`, plus the env from Global Constraints.

- [ ] **Step 5: Implement `lib.rs` and the config.**
  - **Window `main`:** loads `splash/index.html` first. 1440×900, min 900×600, title "Folio", `dragDropEnabled: false`. The plugins are registered here.
  - **Start-up thread:** `choose_port(5174, 5, probe)`. If it's reuse, skip `start`; otherwise `start` and store the child. Then `wait_ready(port, 30s)`: true → `navigate("http://localhost:{port}/")`; false → `eval(showError(...))`.
  - **When the server stops:** `CommandEvent::Terminated` while the window is on Folio navigates back to the splash with `?stopped`.
  - **Window close and Dock:** closing the window hides it (`prevent_close`); `RunEvent::Reopen` shows it.
  - **Quit:** `RunEvent::Exit` kills only the stored child.
  - **Splash page:** shows "Starting Folio…". `showError(msg, logPath)` and `?stopped` show the message, the log path and a Restart button.
  - **Restart permission:** the button calls `plugin:process|restart`. That permission (`process:allow-restart`) is granted only to the local splash in `capabilities/default.json`, never to `localhost:5174`.
  - **Bundle:** `externalBin: ["binaries/node"]`, `resources: { "resources/app/": "app/" }`.
  - **Entitlements for the bundled Node:** `cs.allow-jit`, `cs.allow-unsigned-executable-memory`, `cs.disable-library-validation`.
